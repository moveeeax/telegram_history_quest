# Telegram-бот для квеста «Иван Грозный в эпоху Великих реформ»

## Описание проекта
Этот проект представляет собой Telegram-бот, реализующий интерактивный исторический квест. В квесте Иван Грозный «попадает» в эпоху Великих реформ Александра II (1860-е годы). Бот отправляет унифицированные «карточки» с изображениями, текстом сюжета/задания и кнопками для выбора ответов. Задания хранятся в текстовых файлах в папке `tasks/`, что позволяет легко добавлять или модифицировать квесты.

Проект создан на Python с использованием библиотеки `telebot` (pyTelegramBotAPI). Подходит для образовательных целей, соответствует требованиям творческого задания по истории и цифровым технологиям (НЭТИ, А.К. Кириллов).

## Требования
- **Python**: 3.11 или выше (проверено на 3.11–3.15). Работает на Windows, macOS и Linux.
- **Зависимости**: `pyTelegramBotAPI` (см. `requirements.txt`).
- **Telegram**: аккаунт для создания бота через [@BotFather](https://t.me/BotFather).
- **Интернет**: для обмена с серверами Telegram.

Альтернатива — Docker, тогда Python на машине не нужен (см. раздел «Запуск в Docker»).

## Быстрый старт

### Шаг 1. Получите токен бота
1. Откройте Telegram и найдите @BotFather.
2. Отправьте `/newbot` и следуйте инструкциям (имя бота и username, оканчивающийся на `_bot`).
3. BotFather выдаст API-токен вида `123456789:ABC-DEF1234ghIkl-zyx57W2v1u123ew11`.

> **Токен — это пароль от бота.** Не вставляйте его в `bot.py`, не показывайте в скриншотах и никогда не коммитьте в git. Бот читает токен только из переменной окружения `TELEGRAM_BOT_TOKEN`. Файл `.env` уже перечислен в `.gitignore` и в `.dockerignore`.
>
> Если токен всё-таки утёк — отправьте `/revoke` @BotFather и получите новый.

### Шаг 2. Установите зависимости
```bash
git clone https://github.com/moveeeax/telegram_history_quest.git
cd telegram_history_quest
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Шаг 3. Задайте токен и запустите бота
```bash
cp .env.example .env                               # затем впишите свой токен в .env
export TELEGRAM_BOT_TOKEN='123456789:ваш-токен'    # Windows: set TELEGRAM_BOT_TOKEN=...
python bot.py
```
В Telegram найдите бота по username и отправьте `/start`. Остановить бота — `Ctrl+C`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — (обязательна) | Токен от @BotFather. Без неё бот не стартует. |
| `TASKS_DIR` | `tasks` | Каталог с файлами этапов. |
| `LOG_LEVEL` | `INFO` | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR`. |

Логи пишутся в stdout, и токен из них вычищается — в том числе из текста сетевых ошибок, куда `requests` подставляет URL вида `https://api.telegram.org/bot<TOKEN>/getUpdates`.

## Запуск в Docker
```bash
cp .env.example .env      # впишите TELEGRAM_BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```
`.env` не попадает в образ (см. `.dockerignore`), контейнер работает от непривилегированного пользователя `bot`.

## Тесты
```bash
pip install -r requirements-dev.txt
python -m pytest
```
Тесты проверяют разбор файлов заданий, защиту от чтения файлов вне `tasks/` и целостность самого квеста: что все кнопки ведут на существующие этапы, что каждый этап достижим из `intro` и что квест можно завершить. Прогоняются в CI на Python 3.11–3.15.

## Как писать свои квесты
Задания хранятся в папке `tasks/` как отдельные `.txt`-файлы. Каждый файл — один этап квеста (карточка). Бот читает их по имени файла без расширения.

### Формат `.txt`-файла
Файл в кодировке UTF-8. Структура:
```
Текст: [Сюжетный текст + задание/вопрос. До 1024 символов — таков лимит подписи к фото в Telegram.]

Image: [URL картинки, например с Wikimedia.]

Buttons:
[Текст кнопки 1]: [имя_следующего_этапа | wrong_имя_этапа | end]
[Текст кнопки 2]: [имя_следующего_этапа | wrong_имя_этапа | end]
```
- **Текст**: сюжет + исторический факт. Если текст длиннее 1024 символов, бот отправит картинку и текст двумя сообщениями.
- **Image**: ссылка на картинку. Если секции нет, бот отправит обычное текстовое сообщение.
- **Buttons**: каждая строка — «текст кнопки: callback». Строки без двоеточия пропускаются с предупреждением в лог.
  - `имя_этапа` — перейти к файлу `имя_этапа.txt`.
  - `wrong_<этап>` — показать разбор неправильного ответа из файла `wrong_<этап>.txt`.
  - `end` — завершить квест.

Имя этапа может состоять только из латинских букв, цифр, `_` и `-` (до 64 символов). Всё остальное бот отклоняет: `callback_data` приходит от клиента и не является доверенным, поэтому имя не должно превращаться в путь к произвольному файлу на диске.

### Пример: новый файл `new_stage.txt`
```
Текст: Иван встречает Александра II. «Что за реформы?» Факт: Великие реформы 1860-х модернизировали Россию, отменив крепостное право.

Image: https://example.com/alexander_ii.jpg

Buttons:
Освобождение крестьян: zemstvo
Опричнина: wrong_new_stage
```

### Добавление этапа
1. Создайте `.txt` в `tasks/`.
2. В предыдущем этапе добавьте кнопку со ссылкой на новый (например, `Мой новый этап: new_stage`).
3. Запустите `python -m pytest` — тесты сразу скажут, если этап оказался недостижим или ссылается в никуда.
4. Перезапустите бота.

### Текущая структура квеста
```
intro → reforms → perepis → kill → peasant → zemstvo → judicial → military → final → end
```
У каждого этапа есть парный файл `wrong_<этап>.txt` с разбором неправильного ответа, который возвращает игрока в основную ветку.
